# M1 — first real tabletop adapter

Phase 1 selects one source family and makes it production-shaped while keeping
the `ProjectAdapter -> DesignSnapshot` boundary generic. The selected path is
tabletop, with Crisis Wardens as the pilot.

## Delivered

| Requirement | Implementation | Verification |
|---|---|---|
| Drive manifest | A native, game-owned Google Sheet is checked against `playtrace.toml` before ingestion. File IDs, source kinds, roles, and schemas must agree. | Unit test plus Crisis Wardens replay |
| Docs/Sheets snapshotting | `GoogleWorkspaceGateway` reads native Drive metadata, tabbed Docs, and bounded Sheet ranges. `FixtureWorkspaceGateway` replays captured responses. | Adapter and normalisation tests |
| Stable IDs | Docs accept explicit `[PT-ID:...]` markers and otherwise derive source-scoped fingerprints. Sheets require visible ID columns declared by each game. | Doc and Sheet adapter tests |
| CNL grammar/compiler | A packaged Lark grammar compiles triggers, conditions, permissions, obligations, costs, limits, choices, setup, transfers, and state changes to typed `RuleIR`. | Grammar-family test and adapter integration test |
| Semantic patches | Typed Doc and Sheet patches carry source identity, expected content, and required revision/version. The executor preflights every operation and supports dry-run before native writes. | Success, dry-run, and conflict tests |

## Crisis Wardens acceptance run

The canonical game sources remain in Drive and the game-specific files remain
in `C:\AnalogueGames\crisiswardens`. The 2026-08-25 capture contains a bounded
selection of status-bearing GDD and rulebook passages and every populated row in
the four declared card tables.

The command below completed successfully:

```powershell
uv run playtrace snapshot C:\AnalogueGames\crisiswardens `
  --fixture C:\AnalogueGames\crisiswardens\tests\fixtures\workspace.json `
  --db C:\AnalogueGames\crisiswardens\.playtrace\playtrace.db `
  --output C:\AnalogueGames\crisiswardens\.playtrace\snapshot.json
```

Observed result:

- 4 source revisions: manifest, GDD, rulebook, and cards;
- 40 design entities;
- 302 provenance-bearing assertions;
- authored-status totals of 2 confirmed, 270 working, 28 placeholder, and 2 open questions;
- no unresolved assertion subjects.

This checks a real mixed-medium path, not merely file parsing: the Drive registry
must match local policy, native structures pass through separate Docs and Sheets
normalisers, and their records converge into one source-neutral
`DesignSnapshot`. The same `SnapshotAnalyzer` and SQLite store used by M0 then
accept that snapshot without source-specific branches.

## Deliberate boundaries

- The replay fixture is evidence of a specific observation, not a live-sync
  cache. A live run uses `--access-token-env ENV_VAR` to supply OAuth credentials
  to `GoogleWorkspaceGateway` without placing a token on the command line.
- Unmarked Doc prose is retained as an entity but is not promoted to a mechanic.
- The stable-ID/CNL changes for the current rulebook are a game-owned proposal;
  the canonical Doc was not edited during this milestone.
- Native writes are opt-in. Patch execution defaults to dry-run and aborts if
  revision, version, text, or cell values have changed.
