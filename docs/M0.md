# M0 — Shared kernel skeleton

**Status:** implemented  
**Acceptance:** 15 automated tests passing  
**Pilot fixture:** synthetic and source-medium neutral

## Outcome

M0 implements the shared reasoning skeleton described by Phase 0. It proves
that a semantic `DesignSnapshot` can be analysed without the kernel depending
on whether its source adapter represents Drive, Git, a mixed project, or a
synthetic fixture.

M0 does not integrate Crisis Wardens directly. Every real game has its own Git
repository and owns its adapters' configuration, curated assertions, evidence,
and integration fixtures. Crisis Wardens becomes the first real project after
this shared acceptance boundary.

## Implemented components

| Phase 0 requirement | Implementation |
|---|---|
| Pydantic core objects | `Intent`, `DesignSnapshot`, `EvidenceClaim`, `Hypothesis`, and `ChangeSet` are strict, immutable Pydantic v2 models in `src/playtrace/models.py`. Supporting records cover entities, assertions, evidence links, source revisions, and authored status. |
| Explicit workflow graph | `src/playtrace/workflow.py` declares every allowed stage transition. Invalid jumps fail deterministically; workflow runs return new immutable state. |
| SQLite/FTS5 | `src/playtrace/storage.py` persists snapshots, claims, and workflow runs and exposes FTS5 search. The database is disposable working state. |
| LLM executor abstraction | `src/playtrace/llm.py` defines one typed task/result contract with HTTP, CLI, and deterministic static executors. Executors cannot redefine the workflow. |
| Provenance/dependency primitives | Source revisions and exact source locations are represented in the core models. `src/playtrace/dependencies.py` rejects cycles and computes transitive impact. |
| JS review shell | `src/playtrace/review/` renders a claim, its evidence relations, authored-status counts, deterministic findings, hypothesis, and semantic digest. `playtrace review` serves it locally. |

The deterministic analysis path lives in `src/playtrace/analysis.py`. The
synthetic project-adapter boundary and fixture live in
`src/playtrace/adapters.py`; the fixture is deliberately invented rather than
copied from a real game repository.

## Success criterion

The acceptance test creates the same synthetic semantic game through adapters
declaring different source media. Adapter IDs, source locators, and source media
are different. The shared analyzer must nevertheless produce exactly the same:

- semantic digest;
- entity and assertion counts;
- authored-status counts;
- deterministic findings;
- omission register; and
- dependency impact set.

`tests/test_source_neutral_analysis.py` checks Drive versus Git, Git versus
synthetic, and Drive versus mixed sources. The analyzer intentionally excludes
transport details, extraction timestamps, and adapter identity from the semantic
digest while those details remain available as provenance.

## M0 boundaries

Implemented in M0:

- shared typed contracts;
- deterministic analysis and dependency propagation;
- rebuildable SQLite/FTS5 state;
- provider-neutral model execution boundary;
- read-only review presentation; and
- a synthetic cross-medium acceptance fixture.

Not implemented in M0:

- a real Drive or game-repository adapter;
- controlled-natural-language parsing;
- source mutation or approval application;
- simulation, telemetry, embeddings, or automated critics;
- a production HTTP/API service; or
- Crisis Wardens game-specific state in this repository.
